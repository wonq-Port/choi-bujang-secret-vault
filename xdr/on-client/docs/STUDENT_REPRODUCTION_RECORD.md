## 1. 원문 식별 정보

아래 값은 **실제 Git 작업 폴더와 제출할 커밋에서 확인해 채운다.** 업로드된 원본 ZIP에는 `.git` 디렉터리가 없으므로 이 문서 작성 시점에는 원격 저장소, 브랜치, 최종 커밋을 확인할 수 없다.

| 항목 | 실제 확인값 |
|---|---|
| 저장소 URL | 미기록 — 실제 `origin` 주소 확인 후 입력 |
| 브랜치 | 미기록 — `git branch --show-current` 결과 입력 |
| 제출할 커밋 SHA | 미기록 — `git rev-parse HEAD`의 40자리 SHA 입력 |
| 커밋 작성 시각 | 미기록 — 실제 Git 커밋에서 확인 |
| 커밋에 포함된 문서 | 미확인 — README, `docs/STUDENT_RUNBOOK.md`, 이 문서가 제출 커밋에 포함됐는지 확인 필요 |
| 재현용 새 폴더 | 미기록 — 기존 작업 폴더 밖의 새 경로 입력 |

저장소 URL에 사용자명·비밀번호·토큰 등 인증 정보가 포함되어 있으면 이 문서에 기록하지 않는다. 비공개 저장소는 공개로 바꾸지 않는다.

### 기존 작업 보존 확인

기존 Git 최상위 폴더에서 아래 명령을 실행하고, 결과를 별도로 보존한다. `git status --short`에 변경 사항이 있으면 내용을 확인하기 전까지 초기화·체크아웃·덮어쓰기를 하지 않는다.

```powershell
git status --short
git remote get-url origin
git branch --show-current
git rev-parse HEAD
```

## 3. 동일 커밋을 새 폴더에서 재현하는 절차

1. 원래 작업 폴더와 Git 기록을 보존한다. 위의 원본 보존 확인을 먼저 수행하고, 미커밋 변경이 있으면 그 내용을 검토한다.
2. 실제 제출할 커밋이 원격에서 내려받을 수 있는지 확인한다. 비공개 저장소라면 이미 승인된 Git 인증 방식을 사용하며, 토큰을 명령행이나 문서에 넣지 않는다. 원격에서 받을 수 없는 커밋은 임의로 다른 커밋으로 대체하지 말고 해당 단계의 공식 원문 내보내기 절차를 따른다.
3. 기존 폴더 바깥의 새 경로를 정해 저장소를 복제한다. 아래 예시의 두 자리 표시값은 실제 값으로 바꾸고, 그대로 실행하지 않는다.

```powershell
git clone "REPLACE_WITH_REPOSITORY_URL" "REPLACE_WITH_NEW_EMPTY_FOLDER"
git -C "REPLACE_WITH_NEW_EMPTY_FOLDER" checkout --detach "REPLACE_WITH_40_CHARACTER_COMMIT_SHA"
git -C "REPLACE_WITH_NEW_EMPTY_FOLDER" rev-parse HEAD
git -C "REPLACE_WITH_NEW_EMPTY_FOLDER" status --short
```

4. `rev-parse HEAD` 결과가 1절에 기록할 제출 커밋 SHA와 정확히 같은지 확인한다. 다른 값이면 이 실행 결과를 제출 커밋의 재현 결과로 기록하지 않는다. 원본 작업 폴더에서 파일을 복사해 차이를 감추지 않는다.
5. 프로젝트 구조에서 `on-client` 앱 폴더를 찾고, 해당 폴더에 `package.json`, `tools/start-alekov.ps1`, `src/server.mjs`, `student/extension.mjs`가 있는지 확인한다. Git 최상위 폴더와 앱 폴더가 다른 위치임을 유의한다.
6. `docs/STUDENT_RUNBOOK.md`가 같은 체크아웃에 포함되어 있으면 해당 문서의 런타임 확인·실행·브라우저 확인·종료·재실행 절차를 따른다. 이 문서가 없으면 21단계 문서가 최종 커밋에 반영되지 않은 것이므로 재현 완료로 표시하지 않는다. 현재 제공된 ZIP에는 이 파일이 없어, 실제 저장소에 반영됐는지 별도 확인이 필요하다.
7. 앱 폴더에서 아래 정보를 기록한다.

```powershell
node --version
npm --version
npm run check
```

8. 앱 폴더에서 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

9. 스크립트의 정상 시작 문구를 기록하고 브라우저에서 `http://127.0.0.1:5189/`을 연다. 포트를 변경한 경우 실제 포트를 기록한다. 서버 응답은 AI·SDP·XDR 연결 성공을 뜻하지 않는다.
10. 앱 실행 PowerShell 창에서 `Ctrl+C`로 종료한다. 같은 새 폴더·같은 커밋에서 실행 절차를 한 번 더 수행하고, 재실행 결과를 별도 기록한다.
11. 확인 시각, 터미널 관찰, 브라우저 상태를 기록한다. 캡처나 로그에는 키·토큰·비밀번호·개인 자격·설정 파일 원문을 포함하지 않는다.

### 결과 상태의 사용

- `재현됨`: 동일 SHA의 새 폴더에서 해당 동작을 직접 확인했고, 근거를 남겼을 때만 사용한다.
- `재현 안 됨`: 동일 SHA에서 동작이 실패한 사실을 직접 관찰했을 때 사용하고 오류와 복구 시도를 기록한다.
- `연결 없음`: 구현이 연결 없음 상태를 반환하거나 실제 연결 구성이 없음을 관찰한 경우다. 기능 성공으로 세지 않는다.
- `예제(demo)`: `DEMO_ONLY`/예제 데이터임을 명시한다. 실제 시스템 성공으로 세지 않는다.
- `확인 불가`: 현재 응답이나 근거만으로 판정할 수 없을 때 사용한다.
- `미확인`: 아직 검사를 수행하지 않았을 때 사용한다.

한 단계 안에서 일부 동작만 확인했다면 확인한 동작과 미확인 동작을 나눠 적는다. 서로 다른 커밋에서 나온 결과를 하나로 합쳐 최종 버전 전체가 재현됐다고 표시하지 않는다.

### 백업 및 복원 순서

1. **코드 백업:** 원본 작업 폴더의 현재 상태를 확인하고, 제출할 최종 변경을 Git 커밋으로 고정한다. 커밋 SHA를 기록하고 새 폴더에서 동일 SHA가 체크아웃되는지 확인한다.
2. **설정 백업:** 승인된 외부 보관 위치의 설정은 담당자 절차를 따른다. 원본 `.env`, 네이티브 호스트 설정, SDP 개인 설정을 프로젝트나 새 폴더에 복사하지 않는다.
3. **운영 데이터 백업:** 해당 원천 담당자가 제공한 백업 절차·보관 위치·복구 권한을 확인한다. 지원 절차가 없으면 임의로 데이터베이스를 복사하거나 운영 기록을 내보내지 말고 `확인 불가`로 기록한다.
4. **코드 복원:** 새 폴더에 동일 저장소·동일 SHA를 체크아웃한다. 원본 작업 폴더를 복원 대상 폴더로 사용하지 않는다.
5. **운영 데이터 복원:** 권한이 확인된 경우에만 해당 원천 소유자의 복구 절차를 사용하고, 복원 후 소유자 범위·기록 무결성·읽기 결과를 별도로 검증한다. 화면이 열렸다는 이유로 데이터 복원이 성공했다고 표시하지 않는다.
6. **결과 기록:** 백업·복원 대상, 승인 주체, 실행 시각, 관찰 결과, 실패·제한을 기록한다. 비밀값과 민감한 데이터 본문은 이 문서에 기록하지 않는다.

| 백업·복원 확인 항목 | 결과 |
|---|---|
| 원본 폴더·기존 Git 기록 보존 | 미확인 |
| 원본 Git 상태와 SHA 기록 | 미확인 |
| 외부 인증 설정을 복사하지 않았는가 | 미확인 |
| SDP/XDR 데이터 백업 절차·소유자 확인 | 미확인 / 담당 절차 필요 |
| 별도 SQLite DB 구성 여부 | 미확인 — 기본 구성은 미설정으로 간주하며 실제 호스트 설정을 확인해야 함 |
| 백업 파일을 사용한 실제 복원 | 수행하지 않음 |
| 복원 후 데이터 무결성 검증 | 미확인 |

## 6. 알려진 미해결 사항과 릴리스 판단

1. **최종 Git 원문 미확인:** 제공 ZIP에 `.git`이 없으므로 실제 저장소 URL·브랜치·40자리 최종 SHA를 확인하지 못했다.
2. **21단계 문서 누락:** 현재 제공된 ZIP에 `docs/STUDENT_RUNBOOK.md`가 없다. 실제 제출 커밋에 들어 있는지 확인하고, 누락됐다면 21단계에서 준비한 변경을 먼저 반영한 뒤 새 최종 커밋을 만들고 그 SHA로 재현 절차를 다시 시작한다.
3. **버전 표기의 불일치:** 패키지·README `0.2.11`, 제공 기준 문서 `0.2.9`, 서버 진단 `0.1.0`이 서로 다르다. 원문 근거와 승인 없이 숫자를 통일하지 않았다.
4. **실제 운영 연결 미완료:** 과제 안내상 19단계 실제 보안 조치 집행 연결은 준비되지 않았다. 시연이나 모의 데이터 결과를 실제 운영 성공으로 표시하지 않는다.
5. **새 환경 실행 미확인:** 이 문서는 양식만 제공한다. Windows PowerShell 새 폴더 실행·브라우저 확인·종료·재실행 결과는 사용자가 직접 관찰해 기록해야 한다.

현재 릴리스 상태는 **검증 중**이다. `v1.0`, 운영 인증 완료, 실제 보안 조치 성공 또는 22단계 통과라고 표시하지 않는다. 포털의 원문 전달 완료와 AI 검토 통과는 별도 결과이므로 각각 실제 화면에서 확인한다.

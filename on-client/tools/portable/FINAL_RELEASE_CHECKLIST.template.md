# 케셰브 최종 릴리스 준비와 직접 실행 기록

이 문서는 21단계 설명서와 22단계 새 환경 실행을 준비하는 학생용 기록 틀입니다. 빈칸은 **미확인**입니다. 파일이 존재하거나 준비 검사 결과에 해시가 맞는다고 나와도 실행 성공이나 공식 단계 통과가 확인된 것은 아닙니다. 이 도구는 공식 접수·완료 상태를 바꾸지 않습니다.

## 1. 작업하던 원본과 기존 기록 보존

- 원래 프로젝트 위치: 미확인
- 1~3차 소스·DB·제출물·성취 기록을 보관한 위치: 미확인
- 원본 확인 시각과 파일별 해시/백업 기록 위치: 미확인
- 최종 소스를 커밋한 값(`git rev-parse HEAD`): 미확인
- 저장하지 않았거나 커밋하지 않은 학생 변경: 미확인

원본 폴더·DB를 지우거나 새 패키지로 덮어쓰지 않습니다. 실행 시험에는 별도의 빈 폴더와 별도의 시험 자료를 씁니다. 운영 사용자나 실제 대상에 조치를 실행하지 않습니다. 비밀번호·토큰·인증서·개인정보·DB 내용은 이 기록이나 캡처에 붙이지 않습니다.

## 2. 21단계 설명서 작성

학생이 작성한 설명서 파일: 미확인. 제공 설명서를 그대로 제출한 것으로 기록하지 않습니다.

1. PowerShell을 새로 실행한 상태에서 필요한 Node 버전, 실제 폴더 이동, 실행·중지·재시작 순서를 적습니다. 직접 확인하지 않은 명령에는 **확인 필요**라고 씁니다. `package.json`에 있는 명령인지 먼저 읽고 확인합니다.
2. 브라우저 → 케셰브 서버 → 기존 접속·XDR 서버, 케셰브 서버 → 수업용 AI/개인 AI 관계를 글로 그립니다. 상자마다 실제 파일이나 비밀 없는 주소를 적습니다. 없는 연결은 **미연결**로 표시합니다.
3. 제공 파일/학생 구현 목록을 나누고, `student/extension.mjs`의 각 함수가 어떤 상태·실패를 표시하는지 적습니다. 실제 작성한 어댑터와 새 파일도 포함합니다.
4. 화면에 나타나는 연결 없음·권한 준비 중·조회 실패·확인 불가·한도·취소 안내와 사용자가 할 일을 정리합니다. 확인하지 않은 오류 문구를 지어내지 않습니다.
5. 예제 자료, 개인 AI, 수업용 AI, 실제 접속 서버, 실제 조치 집행은 각각 어떤 상태인지 적습니다. AI가 설명한 것과 서버에서 실제 실행한 것을 구분합니다.

## 3. 패키지 구조 검사

개발 도구가 있는 폴더에서 아래 명령을 실행합니다. 경로는 자신의 실제 폴더로 바꿉니다. 이 명령은 학생 코드를 실행하거나 원본을 수정하지 않고 JSON을 화면에 표시합니다.

```powershell
node tools/check-release-readiness.mjs --source "C:\내작업\on-client"
node tools/check-release-readiness.mjs --source "C:\내작업\on-client" --package "C:\내보내기\keshev"
```

`PACKAGE_MANIFEST.json`과 실제 파일의 SHA256·크기가 맞는지, 필수 README·실행 설정이 있는지 봅니다. `needs_preparation`이면 `checks`의 경로와 상태를 확인합니다. `blocked`이면 누락·파일 변조·지원하지 않는 경로·알려진 비밀 패턴 등을 먼저 해결합니다. 비밀값을 대화에 붙이지 않습니다. 패키지의 manifest는 서명된 실행 증거가 아닙니다. `sameSourceBytes`가 맞아도 Git 커밋 결속이나 실제 실행을 인증한 것은 아닙니다.

## 4. 22단계 새 폴더에서 직접 실행

1. 21단계 학생 설명서와 최종 소스를 같은 커밋에 저장합니다. `git status --short`에 학생 변경이 남았다면 무엇이 빠졌는지 먼저 확인합니다. 패키지에 커밋 값이 기록되지 않았다면 **커밋 미기록**이라고 남깁니다.
2. 원래 프로젝트와 다른 빈 폴더에 패키지를 복사합니다. 원래 DB·자격 증명·환경 변수를 통째로 복사하지 않습니다. Node 버전과 새 폴더 위치를 기록합니다.
3. 설명서대로 기본 실행을 합니다. Workbench와 ALEPH 포털을 켜 두지 않은 상태에서 기본 화면이 뜨는지 직접 확인합니다. 기존 서버 연결이 없으면 화면이 미연결·확인 불가로 안내하는지도 확인합니다.
4. 예제 모드가 제공되면 별도로 실행합니다. 예제 자료는 **예제 확인**으로 기록하고 실제 연결 재현으로 쓰지 않습니다.
5. 개인 AI 기능이 제공되면 개인 AI 안내대로 별도로 확인합니다. 실제 본인 권한·사용량·비용을 먼저 확인합니다. API 키는 본인 PC의 비공개 보관 절차만 사용합니다. 개인 AI 성공이 수업용 AI나 기존 서버 연결 성공을 대신하지 않습니다. 권한이 없거나 호출하지 않았다면 **미연결/미확인**으로 남깁니다.
6. 같은 최종 소스에서 아래 기능을 차례로 확인합니다. 수정했다면 새 커밋과 패키지를 다시 구분하고, 서로 다른 소스의 결과를 합쳐 최종 누적 재현이라고 쓰지 않습니다.
7. 서버를 중지하고 다시 켠 뒤 같은 기능을 확인합니다. 원본 학생 파일·기존 기록이 보존됐는지 최초 기록과 비교합니다. 연결에 필요한 실제 권한이 없으면 확인 불가(UNV)로 남깁니다.

## 5. 릴리스 범위 기록

- 확인한 최종 커밋/패키지 manifest SHA256: 미확인
- 기본 실행·개인 AI·원천 연결·실제 조치의 확인 범위: 미확인
- 재시작 결과와 기존 자료 보존 비교: 미확인
- 확인 불가(UNV), 실패, 다음에 확인할 항목: 미확인
- 공식 21·22 접수/완료 확인: 미연결
- 버전: 검증 중

실제 실행 관측과 공식 완료가 확인되기 전에는 준비 도구 결과만으로 `v1.0`, “실제 연결 완료”, “21·22단계 통과”라고 표시하지 않습니다. 확인한 범위와 남은 범위를 기록하면 됩니다.

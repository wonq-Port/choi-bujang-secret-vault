# 수료 후에도 내 보안 Agent 쓰기 (학생용)

과정에서 만든 보안 Agent(기본 이름 케셰브)를 수료 후에도 내 PC에서 실행하고 보관하는 방법을 설명합니다. 워크벤치와 ALEPH 포털이 없어도 실행할 수 있습니다.

## 1. 수료 후에도 되는 것과 안 되는 것

| 구분 | 수료 후 | 설명 |
|---|---|---|
| 앱 실행과 화면 확인 | 됩니다 | `package.json`의 Node 요구 버전을 준비하고 `node src/server.mjs`로 실행합니다. 미연결 기본 실행과 예제 화면에는 외부 npm 패키지와 인터넷이 필요하지 않습니다. 실제 AI·SDP·XDR 연결은 별도입니다. |
| 예제 화면 | 됩니다 | `node src/server.mjs --demo`로 실행합니다. 화면 모양을 보여 주는 예제 자료이며 실제 연결이나 실제 보안 판정이 아닙니다. |
| 내 코드 고치기·보관 | 됩니다 | 내가 만든 `student/` 파일과 고친 파일이 그대로 패키지에 들어갑니다. Git으로 계속 관리할 수 있습니다. |
| 사용자·기기·접속 기록 연결 | 별도 준비가 필요합니다 | 기본 실행은 "연결 없음"입니다. 실제 접근 제어 서버나 XDR 서버, 그 서버에 맞는 연결 어댑터와 인증서가 있어야 합니다. 과정에서 쓰던 학원 서버 연결은 수료 후 유지된다고 보지 않습니다. |
| 앱 안의 AI 설명 기능 | 기본으로 꺼져 있습니다 | 앱 권한이 발급돼야 동작하고, 그 전에는 실제 AI 호출을 막아 둡니다. 학원 수업용 AI 계정과 사용 권한은 수료 후 쓸 수 없다고 보고 준비합니다. |
| 워크벤치·ALEPH 포털 | 필요 없습니다 | 실행에는 필요하지 않습니다. 단계 판정과 제출은 과정이 끝나면 쓰지 않습니다. |

과정에서 구현하지 않은 단계의 기능은 패키지에도 없습니다. 이 패키지를 완성된 보안 제품으로 소개하지 않습니다. 포트폴리오로 쓸 때는 어느 단계까지 구현했는지와 "기본 실행은 연결 없음"이라는 점을 함께 적습니다.

## 2. 수료 전에 패키지로 내보내기

1. 과정에서 쓰던 프로젝트를 마지막으로 커밋해 둡니다.
2. ALEPH 4차 탭의 「수료용 도구·상세 설정 안내 받기」에서 공식 도구 묶음을 받고, `docs/PERSONAL_AI_SETUP.md`의 설치 미리보기와 적용 순서를 따릅니다. 기존 앱을 덮어쓰지 않고 내보내기 도구를 추가합니다.
3. 파일 탐색기에서 on-client 폴더를 열고 주소 표시줄에 `powershell`을 입력해 PowerShell 창을 엽니다.
4. 아래 명령을 실행합니다. `--out`에는 아직 없는 새 폴더 이름을 적습니다. 앱 이름은 생략하면 케셰브로 적힙니다.

```powershell
node tools/export-student-package.mjs --source . --out ..\..\keshev-package --app-name "내 앱 이름"
```

5. `내보냈습니다`와 파일 개수가 보이면 끝난 것입니다. 새 폴더의 `START_HERE.md`를 열어 실행 방법을 확인합니다.

### 내보내기가 멈췄을 때

| 메시지 | 할 일 |
|---|---|
| `EXPORT_OUTPUT_EXISTS` | 이미 있는 폴더는 덮어쓰지 않습니다. `--out`에 새 이름을 적습니다. |
| `EXPORT_OUTPUT_OVERLAP` | 출력 폴더를 on-client 폴더 밖의 다른 위치로 지정합니다. |
| `EXPORT_SOURCE_NOT_ALEKOV` | `--source`가 on-client 폴더인지 확인합니다. |
| `EXPORT_LINK_REFUSED` | 폴더 안에 바로가기(링크)가 있습니다. 파일을 지우지 말고 메시지를 강사에게 보여 줍니다. |
| `EXPORT_SECRET_CONTENT` | 파일 안에 토큰이나 키로 보이는 값이 있습니다. 값을 대화창에 붙여 넣지 말고, 그 키를 발급한 곳에서 폐기한 뒤 파일에서 지우고 다시 실행합니다. 어떻게 할지 모르겠으면 강사에게 파일 경로만 알려 줍니다. |
| `EXPORT_FILE_TOO_LARGE`, `EXPORT_TOTAL_TOO_LARGE` | 과제와 관계없는 큰 파일이 들어 있는지 확인합니다. 지우기 전에 강사에게 확인합니다. |
| `EXPORT_SUPPLIED_CONFLICT` | 기존 파일과 새 제공 안내·도구가 다릅니다. 원본은 그대로입니다. 파일 경로와 차이를 대조하고, 학생이 작성한 내용은 별도 문서로 보존한 뒤 다시 진행합니다. 수정 내용을 모르면 비밀값 없이 경로와 오류 코드로 수업용 AI에 원인을 묻습니다. |
| `EXPORT_SOURCE_CHANGED`, `EXPORT_PARENT_CHANGED`, `EXPORT_WRITE_FAILED` | 작업 중 파일·경로가 바뀌었거나 기록을 마치지 못했습니다. 부분 결과는 자동으로 지우지 않습니다. 표시된 부분 폴더와 원본을 확인한 뒤 새 출력 경로로 다시 진행합니다. |

## 3. 패키지에 들어가는 것과 빠지는 것

- **들어가는 것**: 제공 코드, 내가 만든 `student/` 파일, 내가 고친 파일과 새로 만든 문서, `.env.example`(빈 설정 견본), 시작 틀 목록(`.on-starter-manifest.json`), 내보내기 도구, `START_HERE.md`, 파일 목록과 SHA-256이 적힌 `PACKAGE_MANIFEST.json`.
- **빠지는 것**: `.git`(Git 기록), `node_modules`, `.local`, `receipts`, 캐시 폴더, `.env` 같은 비밀 설정 파일과 인증서·키 파일. 빠진 폴더와 비밀 파일 이름은 목록에 기록하고 내용은 복사하지 않습니다.
- 자격 보관함·연결 등록부, 세션·토큰 설정 자료, DB·로그, `src/learning` 내부 판정 소스·시험 자료도 기본 제외합니다. 알려진 토큰·JWT·비밀 설정 패턴은 거절하지만, 모든 바이너리나 임의 이름의 비밀까지 알아내는 도구는 아닙니다. 포함 목록을 확인하고 공유합니다.
- 실제 0.2.10 시작 틀에 없는 새 안내와 내보내기 도구는 명시적으로 보충합니다. 동명 제공 파일이 다르면 덮어쓰지 않고 중단합니다. `FINAL_RELEASE_CHECKLIST.md`는 없을 때만 틀에서 생성하며, 이미 학생이 작성한 기록은 그대로 복사합니다.
- Git 기록까지 보관하려면 내보내기와 별도로 GitHub 저장소에 올리거나 프로젝트 폴더를 따로 백업합니다. 이때도 `.env`나 키 파일이 커밋되지 않았는지 먼저 확인합니다.

## 4. 내보낸 패키지 실행하기

`START_HERE.md`에 같은 내용이 있습니다.

원본에 수료용 독립 실행 구성이 설치돼 있다면 `START_HERE.md`의 명령은 `node src/standalone-server.mjs`입니다. 그렇지 않은 고정0.2.10은 아래 기존 명령을 사용합니다. 새 entry만 있고 관련 모듈·화면이 빠졌으면 내보내기가 중단됩니다. 앱 이름 옵션은 설명과 목록 이름만 바꾸며 새 독립 실행의 실제 앱 이름은 프로젝트 밖 개인 설정의 appName으로 지정합니다.

```powershell
node src/server.mjs
```

브라우저에서 `http://127.0.0.1:5189`를 엽니다. 포트가 겹치면 `$env:ON_PORT=5190`을 먼저 실행합니다. 끝낼 때는 `Ctrl+C`를 누릅니다. 이 앱은 내 PC(127.0.0.1)에서만 열리며, 다른 PC에서 접속하도록 공개하지 않습니다.

## 5. 파일 확인과 다시 내보내기

- 패키지 폴더에서 `node tools/export-student-package.mjs --verify .`를 실행하면 목록과 실제 파일을 다시 대조합니다. 내 코드를 고친 뒤에는 달라지는 것이 정상입니다.
- 목록은 원본 요구 Node 버전과 내보내기 시 사용한 Node 버전, 필수 파일·크기·해시·합계를 기록합니다. 목록 자체는 배포 주체를 인증하는 서명이 아닙니다.
- origin의 student·student-added·provided-modified는 위치와 이전 제공 목록의 해시 비교 결과입니다. 작성자나 학생 성취를 인증하지 않으며, 새 제공 개인 AI 파일이 student-added로 표시돼도 학생 작성·공식 통과 근거로 쓰지 않습니다.
- 고친 버전을 새로 보관하려면 원래 on-client 폴더나 이 패키지 폴더를 `--source`로 지정해 새 이름의 폴더로 다시 내보냅니다. 이전 패키지는 그대로 남습니다.

## 6. 회사나 개인 서버에 연결하고 싶을 때

주소와 키만 바꾸면 바로 연결되는 구조가 아닙니다. 아래가 모두 준비돼야 하며, 준비 전에는 기본 "연결 없음" 상태로 쓰는 것이 맞습니다.

- **접근 제어·XDR 서버 연결**: 그 서버의 API에 맞춘 연결 어댑터 모듈(`ON_ENGINE_ADAPTER`)이 필요합니다. 연결 형식은 `docs/IMPLEMENTATION_CONTRACT.md`에 있습니다. 서버 관리자가 허락한 범위에서만 연결하고, 다른 사람의 기록을 조회하는 관리자 API를 연결하지 않습니다.
- **SDP 연결**: 서버 담당자가 발급한 개인 설정 파일과 인증서가 필요합니다(`docs/SDP_HOST_CONNECTION.md`). 설정 파일과 인증서는 패키지·Git·압축 파일 밖에 보관합니다.
- **수업용 AI**: 기존 앱 권한을 발급하는 AI 게이트가 필요합니다(`docs/AI_SETUP_GUIDE.md`).
- **수료 후 개인 AI**: 새 개인 실행 경로가 함께 제공된 경우 [개인 AI 설정](PERSONAL_AI_SETUP.md)을 따릅니다. 개인 설정·키는 프로젝트 밖에 두고 Git·패키지에 넣지 않습니다. 개인 AI 응답은 공식 과제 판정이나 실제 보안 조치 성공을 뜻하지 않습니다. 실제 공급사 유료 호출은 이번 패키지 검사에서 실행하지 않았습니다.

설정을 넣었다고 연결이 성공한 것은 아닙니다. 화면에서 실제 사용자·기기 정보와 판정 결과가 보이는지 확인합니다.

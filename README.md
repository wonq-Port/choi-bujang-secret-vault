# BYTE BACK 방어전 시작 틀 R5

이 저장소는 1단계에서 학생 본인이 GitHub 저장소와 Vercel 배포를 만드는 출발점입니다. 포함된 메모 네 건은 가상 자료입니다. 실제 학생 자료, 토큰, 비밀키를 넣지 마세요.

## 학생이 하는 일: 세 걸음

1. GitHub 계정을 만듭니다.
2. 방어전 1단계 카드의 **Deploy** 버튼을 누릅니다. Vercel에 GitHub로 로그인하고, 새 저장소가 **본인 계정의 Public 저장소**인지 확인한 뒤 Deploy를 누릅니다.
3. 배포가 끝나면 화면에 나온 `https://…vercel.app` 주소를 방어전 1단계 카드에 붙여넣고 제출합니다. 저장소 주소나 설정 파일은 적지 않습니다.

배포가 끝나면 `/`에서 점령된 가상 자료실을 볼 수 있습니다. `/data.json`에는 같은 가상 메모가 공개됩니다. 이 공개 상태를 확인하는 것이 1단계의 출발점입니다. 1단계 접수와 심판 판정은 포털에서 확인합니다.

## 시작 틀의 자동 처리

`vercel.json`은 정적 결과물 `public`을 배포합니다. 빌드 명령 `npm run build`는 Vercel이 제공하는 GitHub 저장소 소유자·이름, 커밋 SHA, 배포 URL을 검증하고 `public/aleph.json`을 생성합니다. 이 값이 없으면 빌드가 실패하므로, 성공한 것처럼 빈 주소를 내보내지 않습니다. `aleph.json`의 내용만으로 저장소 소유권이나 방어 성공을 인정하지 않습니다. 심판이 공개 저장소의 실제 커밋과 배포된 자료를 따로 대조해야 합니다.

`aleph.config.json`의 `repoUrl`과 `publicAppUrl`은 이전 제출 묶음 방식의 자리표시자입니다. 1단계에서는 학생이 편집하지 않습니다. 2단계 이후 코딩 도구가 필요한 설정과 보호 기능을 단계별로 작성합니다. `npm run bundle`과 `bundle-notes.json`도 1단계의 세 걸음에는 포함되지 않습니다.

로컬에서 가상 화면만 확인할 때는 `npm run build -- --local`을 사용합니다. 로컬 실행은 Vercel 배포나 심판 접수를 증명하지 않습니다. 저장소의 `src/attack-check.mjs`는 실제 배포가 된 뒤 `/data.json`을 비로그인으로 요청해 공개 가상 메모의 확인 표시를 읽습니다.

## 다음 단계의 코딩 도구에 전달할 규칙

[AGENTS.md](AGENTS.md)를 먼저 읽히고 한 번에 한 제작 단위만 요청하세요. 2단계부터는 자료 보호를 구현할 때 `public/data.json`을 복사하는 1단계 빌드 흐름도 함께 바꿔야 합니다. 3단계 이후의 로그인, 허용 경로, 5단계의 원본 API 주소, 6단계 이후 정책 규칙은 해당 단계 원고와 계약에 맞춰 추가합니다. 비밀번호·토큰·서버 전용 키·실제 학생 기록을 코드, Git, 제출 묶음에 넣지 않습니다.

`src/decider.mjs`와 `src/detect.mjs`의 로컬 시험은 반 엔진이나 운영 심판의 결과가 아닙니다. 1단계 이후 제출 묶음 계약 `aleph.defense.submission.v2`는 `scripts/bundle.mjs`에 남아 있으며, 코딩 도구가 해당 단계의 최신 배포 주소와 Git 원격을 맞춘 뒤 사용합니다.

## 10단계: 백업에서 자료실을 되살립니다

### 1. 복원 전 정책 사본 재조회·확인 순서 및 중단 분기
1. **복원 전 정책 사본 다시 조회·확인**: 복원을 실행하기 전에 침해 전에 검증해 둔 안전 정책 사본(`version: "v1.0-verified"`, `policyRevision: 1`)을 다시 조회·확인하여 현재 시험 정책과의 차이(복원할 버전과 바뀔 항목 목록)를 실행 전에 먼저 표시합니다 (`GET /api/restore`). 이때 실제 운영 정책은 건드리지 않습니다.
2. **사본 누락 또는 검증 실패 시 복원 중단 분기**: 다시 조회한 정책 사본이나 비공개 백업 사본이 없거나(`null`/누락), 버전·무결성·해시 검증에 실패한 경우(`verified: false`)에는 **즉시 복원을 중단(HTTP `422` 반환)**하고 어떤 메모나 정책도 변경하지 않습니다.
3. **시험 정책 되돌리기 및 보존 원칙**: 정책 사본 재조회·검증이 통과하고 실행 전에 바뀔 항목을 확인한 경우에만 시험 정책을 검증된 안전 정책 버전으로 되돌리며, 다른 서비스 규칙과 감사 이력은 그대로 보존합니다.

### 2. 비공개 가상 메모 단건 복원 서비스 및 경로 (메모 복원 전용)
- **서비스**: `notes` (`api/memos.js`)
- **메모 복원 경로**: `POST /api/restore`
- **경로 역할 (메모 복원으로 한정)**: 이 `POST /api/restore` 경로는 **비공개 가상 메모 사본에서 시험 계정 B의 지정한 메모 한 건만 복원하는 메모 복원 전용 경로**입니다. 이 경로에는 **정책 변경이나 서비스 규칙 변경이 포함되지 않으며**, 다른 메모(시험 계정 A의 메모 등)와 기존 감사 기록(`auditLogs`), 다른 서비스 규칙은 그대로 보존합니다.
- **실행 전 백업 사본 재검증**: 메모 복원 실행 전 비공개 백업 사본을 다시 읽어 사본의 `ID`, `owner_id`, `내용 SHA-256` 해시를 검증하며, 사본이 없거나 검증에 실패하면 복원을 즉시 중단합니다.

### 3. 복구 후 확인 순서

#### (1) 복원 대상 한 건을 비공개 백업 사본과 대조
시험 계정 B의 메모 한 건을 복원한 직후, 복원된 대상 한 건을 다시 조회하여 **비공개 백업 사본과 아래 세 가지 항목을 각각 대조·확인**합니다.
1. **`ID` 확인**: 복원된 메모 한 건의 `ID`(`id`)가 비공개 백업 사본의 `ID`와 정확히 일치하는지 확인합니다.
2. **`owner_id` 확인**: 복원된 메모 한 건의 소유자 `owner_id`가 비공개 백업 사본의 `owner_id`(시험 계정 B)와 정확히 일치하는지 확인합니다.
3. **`내용 SHA-256` 확인**: 복원된 메모 한 건의 내용으로 계산한 **`내용 SHA-256`** 해시(`contentHash`)가 비공개 백업 사본의 **`내용 SHA-256`** 해시와 정확히 일치하는지 확인합니다.
- 위 세 값(`ID`, `owner_id`, `내용 SHA-256`)이 모두 비공개 백업 사본과 같을 때만 해당 한 건 복원이 일치한 것으로 판정하며, 지정한 한 건 밖의 다른 메모와 감사 기록은 변경되지 않았는지 확인합니다.

#### (2) 복구 뒤 1~9단계 정상·금지 요청 재실행 순서
복구 완료 후 자료와 정책이 정상으로 돌아오고 이전에 막던 공격이 다시 거부되는지 아래 순서로 재시험합니다 (실행하지 않은 시험은 미실행으로 표기).
1. **1~2단계 (비로그인 공개 자료 차단 재확인)**: 비로그인 상태에서 `/data.json` 및 `GET /api/memos` 호출 시 가상 메모가 노출되지 않고 거부(`404`/`401`)되는지 확인 — 미실행
2. **3~5단계 (신원 검증 및 서버 집중화 재확인)**: 시험 계정 A의 정상 토큰으로 `GET /api/memos` 요청 시 정상 허용(`200`)되고, 만료·위조 토큰 요청은 `401`로 거부되는지 확인 — 미실행
3. **6~7단계 (등록 기기 및 이상 접속 재인증 판정기 재확인)**: `npm run decider:test` 및 `npm run fixture:7`을 실행해 미등록 기기 요청은 `deny`(`device_not_registered`), 복합 이상 접속은 `step_up`(`step_up_required`), 등록 기기 정상 요청은 `allow`가 반환되는지 확인 — 미실행
4. **8단계 (구역 분리 및 강사 공지 보호 재확인)**: 시험 계정 B가 시험 계정 A의 자료를 조회·수정·목록 조회(`GET /api/memos/:id`, `PUT /api/memos/:id`, `GET /api/memos?owner_id=...`)하거나 학생 계정으로 강사 공지를 수정할 때 `403`으로 거부되고, 시험 계정 A의 정상 요청은 유지되는지 확인 — 미실행
5. **9단계 (도플갱어 탐지 및 권한 회수 재확인)**: `npm run detect:test` 실행 및 회수된 신원·탈취 세션 토큰으로 재요청·타 자원 이동 시 `401`/`403`으로 차단되고 감사 이력이 보존되는지 확인 — 미실행
